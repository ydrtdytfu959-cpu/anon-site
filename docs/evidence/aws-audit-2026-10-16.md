## Principal findings

1. **P0 historical catalog outage: monthly search budget was exhausted and no reusable Channel3 catalog remained.** Initial runtime cap was 60 and strongly consistent monthly counter was exactly 60. The cache contained only five budget rows, zero page/detail/presentation/cursor rows. The cap increase to 500 removes this particular current cap blockage, but does not itself establish product coverage, relevance, freshness, or prevent repeated broad searches from consuming the new allocation.
2. **P1 retailer coverage is not demonstrated by infrastructure health.** The Channel3 cache had zero available records for all six retailers at the initial/pre-smoke snapshot. The legacy product table held 982 records, all with Nike advertiser ID `4942550`. No stored records proved independent Adidas, Sephora, Levi's, TJ Maxx, or e.l.f. coverage. These are persisted records, not a current stock or acceptance count.
3. **P1 the enabled legacy warm schedule is ineffective.** `AnoX-Catalog-Warm-V2`, enabled every six hours, targets `AnoX-Catalog-API` with `{"action":"warm"}`. The actual deployed code handles only HTTP GET list and detail routes, so this input returns an HTTP-style 404 object without a Lambda execution error. A successful schedule invocation does not mean a cache refresh happened.
4. **P1 the legacy list endpoint has no DynamoDB fallback.** GET /catalog/products always calls CJ GraphQL and writes accepted provider rows into DynamoDB. It never reads a list from DynamoDB. Only details read cached payloads, with a six-hour freshness check. Therefore 982 persisted records do not guarantee list availability during CJ failure.
5. **P1 historical denial events cannot be individually classified from existing telemetry.** The budget implementation collapses month/day/total exhaustion into `UPSTREAM_BUDGET_EXCEEDED`; EMF events carry only event name and count. Recent monthly exhaustion is directly supported by the counter, but which constraint caused every older event is not logged.
6. **P2 unused legacy Channel3 credential access remains.** `AnoX-Catalog-API` has a Channel3 secret environment reference and GetSecretValue IAM grant, but its actual deployed, hash-verified code contains no Channel3 request path. This is unnecessary standing access, not evidence that the current CJ fallback spends Channel3 credits.
7. **P2 uptime checks do not measure six-retailer coverage.** The CloudFormation probe checks health, commerce capabilities, and /catalog/products?limit=1 every 15 minutes. For catalog it accepts a generic JSON object; it neither verifies product count nor tests Channel3 search. The legacy list implementation calls CJ for this request. Three real /catalog/search 429s coexisted with catalog probe HTTP 200s in October 16 access logs.
8. **P2 monitoring configuration has stale or weak context.** Regional concurrency alarm threshold remains 8 even though verified quota is 1,000. Channel3 log group has no configured retention; the 18 current alarms were all OK at initial inspection, often because missing data is treated as nonbreaching. An OK budget alarm means no recent denials in its five-minute window, not that credits remain.
9. **P2 shipping is a separate sandbox integration, not a verified live Algeria delivery system.** Shipping Lambda references only EasyPost sandbox credentials. No current HTTP route, EventBridge target, or Lambda event-source mapping connects it to public shipping creation. The account API exposes read-only shipment/tracking records. Its template requires test-mode EZTK keys. No live carrier rates, labels, Algeria route coverage, customs charges, or guaranteed delivery dates were verified.
10. **P2 the budget month is pinned to October.** Source budget logic fails closed if the configured month differs from the actual UTC month. Keep this protection; plan an owner-authorized November allocation/configuration change without resetting historical October counters.

## Safe release recommendations

- Retain the owner's verified 500/60/200/5 settings and preserve counters; do not expand paid credit settings.
- Integrate validated provider website_ids before upstream searches, use fixed retailer-specific queries/cache keys, and collect accepted/rejected counts with bounded enumerated reasons. Never log product/customer payloads or secret values in metrics.
- Add reason and request-kind classification to budget denials (monthly_search, daily_search, daily_detail, total_daily, rate) without changing reservation atomicity; emit periodic remaining-allocation/expiry status separately from error alarms.
- Preserve provider-authorized presentation cache within documented licensing limits and make cache/budget/source unavailability visible. A wider budget alone is not durable coverage.
- Correct the legacy warmer input or implement a bounded supported warm operation, only in a reviewed change and subsequent owner-approved deployment. Preserve CJ independently; do not repoint its calls through Channel3.
- If offline CJ listing is required, add a bounded query on the existing advertiser/time GSI with appropriate narrowly scoped IAM Query permission and explicit freshness semantics. Do not silently treat old cached prices as current.
- Remove unused Channel3 secret access/environment from legacy Catalog-API in a reviewed deployment, after preserving the hash-verified CJ-only call path. Restrict temporary QA lifecycle and unused integrations through an explicit cleanup plan.
- Replace broad legacy catalog probing with provider-free readiness/cache-coverage diagnostics; alert separately on each retailer's usable coverage and data age. Do not run new scheduled provider refreshes without budget allocation.
- Correct stale concurrency alarm description/threshold, add sensible explicit log retention, and verify monitor-to-action meaning. Alarm OK is not a catalog acceptance criterion.
- Keep shipping and fee/payment activation gated. Current evidence supports sandbox EasyPost infrastructure and account tracking reads, not live Algeria logistics or retailer checkout authority.
