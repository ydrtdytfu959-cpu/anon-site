## Completed behavior

- The retained provider registry supports native Channel3 cursors alongside offset providers. The backend sends the documented `page_token` request parameter and returns the upstream `next_page_token` as the next cursor. Cursor associations bind query/section/filter/limit context for 30 minutes. Explicit restart is required for expired/invalid cursors; failures preserve accepted products, and stale/aborted work cannot replace current state. Stable provider/product identities deduplicate overlaps. Discovery contexts load lazily and retain independent pagination; search is separate. Status updates use `channel3-live` without changing Nike/CJ identities.
- New product detail hydration uses the official product endpoint, preserving real descriptions, specifications, brand, merchant offers, all accepted images and selected options. Direct product URLs survive reopening. Interactive thumbnails, keyboard/swipe controls and bounded lazy loading serve the full detail gallery; cards keep one primary image and the existing pixel budget. Real provider limits are enforced (64 detail images and a 256 KiB sanitized payload); excessive payloads fail explicitly instead of silently truncating product information. Unknown inventory remains unknown.
- Requested options and effective provider selections are compared. Relaxed selections require acceptance, and a requested merchant cannot silently become another merchant. A 30-second validity bound and visibility checks remove expired price, availability and offer links. Manual retry/refresh has no background polling loop.
- A separate persistent cart saves selected identifiers, merchant/condition/options, quantities and attribution metadata without claiming purchase authorization. Storage is bounded to 50 lines and quantities 1–20. Web Locks and fresh storage reads serialize edits across tabs; stale edits fail. Unsupported locking/storage falls back to an explicit session-only state. Corrupt restoration is visible. Explicit browser-data erasure cancels pending mutations and removes saved selections.
- Authenticated server quotes reject browser prices, hydrate fresh offers through IAM-only catalog invocation, validate exact selections and bind customer/cart/idempotency. Quotes support 10 lines/five distinct selected products, three concurrent hydrations, and a nine-second upstream deadline. Exact decimal-to-minor-unit arithmetic avoids floating-point financial rounding. Quotes expire no later than their earliest product snapshot and never exceed five minutes.
- Product subtotal remains an estimate until a purchasing provider guarantees it. Tax, domestic/international shipping and import costs remain explicitly unknown. The AnoX fee is exactly 500 USD cents per successfully completed order, shown separately as conditional. USD-to-USD conversion is explicitly zero. Neither a verified payable nor guaranteed delivered total is invented.
- Namespaced owned quote, attempt and order records use conditional writes and atomic audit/idempotency transactions. Blocked attempts create no order or payment. Server order/payment state is authoritative; client redirects and local flags cannot confirm payment. Cancellation/refund capabilities remain unsupported.
- CheckoutProvider interfaces and disconnected Stripe-signature/state foundations are implemented and tested. The HTTP payment handler is disabled and no webhook route, payment credentials or payment permission is provisioned. An environment/browser flag cannot activate arbitrary merchant purchases.

## Cache and usage controls

Search and discovery retain the existing dedicated encrypted, on-demand DynamoDB cache. Deterministic versioned keys distinguish normalized NFC/whitespace query, context/section, canonical filters, limit and opaque cursor. Search TTL is five minutes; discovery TTL is ten minutes. These short browsing snapshots bound staleness while sharing metered results across users. Expired snapshots refresh; failures/malformed entries cannot poison a successful cache or bypass required storage. In-process coalescing and distributed leases prevent identical misses from unnecessarily multiplying calls.

Detail data is different: each sequential display/quote reads fresh volatile price/availability/offer data. Concurrent requests that started before a shared fetch completed may share its 30-second result exchange. A one-hour presentation-only cache can provide descriptive fallback after a failed refresh, but strips offers, prices and availability. Quotes reject that fallback. No price is cached indefinitely.

Shared atomic budgets default to 1,000 paid searches/day, 5,000 free detail requests/day and five upstream requests/second. Cache hits consume no upstream reservation. Storage failures fail closed; an expired rate-slot reservation cannot release a later burst. Separate structured CloudWatch counts identify hit/miss, upstream request/failure, paid/free usage, fallback, budgets and rate limits. Logs omit credentials, authorization headers and customer payloads. Staged alarms cover usage, errors, budget failures, throttles, latency and table writes. Notifications require an existing approved SNS topic.

Provider policy limitation: current Channel3 guidance requires fresh volatile product fields on display. The new detail/quote flow follows that rule. Approval for the retained five/ten-minute catalog-card price snapshots, or a separately approved card-display policy, is a release prerequisite. This work does not claim full contractual approval or create a per-card refresh fanout.

## Explicit limitations and release requirements

- No official authorized Channel3 merchant-purchasing contract or participating-merchant payment arrangement has been established. Catalog coverage is not purchasing permission. Checkout, fee collection, actual order creation and operational cancellation/refund remain disabled.
- Stripe Connect charge type, merchant onboarding, responsibility and multi-merchant flow require commercial/technical decisions. A connected sandbox inventory is not a tested integration. Signature tests use local fixtures; no real sandbox/live financial call occurred.
- Current shipping infrastructure supports post-payment fulfillment and does not establish measured precheckout rates, U.S. receiving/tax inputs, Algeria duties or guaranteed arrival costs for these routes. A final landed total remains unavailable until these inputs/contracts exist.
- New details/commerce endpoint, real Cognito, distributed DynamoDB transaction, IAM and CORS tests require approved staging deployment and authorized test accounts. Local transport tests do not substitute for them. Current route/stage/concurrency quotas must be checked at deployment time.
- Synchronous Lambda cancellation cannot stop an already running catalog invocation; at most three in-flight reads may finish after caller cancellation. Queued reads stop and upstream budgets still apply.
- Persistent order/audit data needs an approved retention policy. Alarm destinations and capacity/abuse thresholds need operational ownership before release.
- The complete HTML contains its client scripts/styles and matching CSP, but live products/auth/quotes still depend on documented AWS services and provider media. Deploy the backend prerequisites before the frontend; publishing the HTML alone does not activate those routes.
