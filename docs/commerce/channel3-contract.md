# Official Channel3 detail and purchasing evidence

Reviewed 2026-10-09; public docs only, no credential retrieval or merchant orders.

- [Product Detail API](https://docs.trychannel3.com/api-reference/v1/product-detail): `GET https://api.trychannel3.com/v1/products/{product_id}`, required `x-api-key`; direct Product response. Optional locale, units and `website_ids` query fields; optional `x-user-id` changes attribution on buy links. Documented401/402/404/422/500 responses. FixedUS/USD/en is AnoX's current purchasing-market assumption, not Algeria merchant coverage.
- [Detail guide](https://docs.trychannel3.com/guides/product-detail) and [pricing](https://docs.trychannel3.com/pricing): product retrieval is free; search/lookup cost1credit. Free detail requests still consume rate/daily quota.
- [Variants](https://docs.trychannel3.com/variants): exact `option_<OptionName>=<Label>` selection parameters. Server may relax impossible selections; `variants.selected` is the actual configuration. Compare it with requested options. Values with a different `product_id` navigate to another product. Search per-value availability is null; detail hydrates it. No inventory quantity is supplied.
- API OpenAPI currently restricts offer/option availability to `InStock`/`OutOfStock` and condition to `new`/`used`; prose variant/offer guides mention older additional states. Use the concrete public schema; treat unexpected availability as unknown, not stock.
- [Images](https://docs.trychannel3.com/guides/images): one images array, fields `url`, optional `cleaned_url`, `alt_text`, `shot_type`, `is_main_image`. Cleaned image is for cards; original hosted image supports detail galleries. No separate gallery endpoint is documented.
- [Offers](https://docs.trychannel3.com/guides/offer): price and attribution belong to a merchant offer. Actual API schema is `price.price` plus `price.currency`, despite an older prose example using `amount`. Preserve `domain`, URL, condition, commission rate and nullable dimensions; do not fabricate offer IDs or fulfillment weight.
- [Lookup](https://docs.trychannel3.com/api-reference/v1/lookup-product): POST `/v1/lookup` body `{url,max_staleness_hours?}`; minimum staleness1hour/default3hours; returns `{product}`. Existing product IDs should use free detail retrieval instead.
- [Caching](https://docs.trychannel3.com/guides/caching): stable IDs/category slugs may persist; presentational fields permit short TTL. Prices, availability and offer URLs must refresh before display. Offer URLs are short-lived. A detail visit and quote must never treat cached prices as refreshed.
- [Rate limits](https://docs.trychannel3.com/faq/rate-limits): default key most endpoints10/s, search10/s, lookup5/s, shared daily quota10000.429 has Retry-After5. Account plan must be verified before increasing local controls.
- [Checkout](https://docs.trychannel3.com/checkout.md) explicitly says coming soon; endpoint details and SDK support will be published later. [Developer page](https://trychannel3.com/developers/) offers early-access contact. No operational checkout contract, merchant-order lifecycle, refunds, or fee-routing authorization was found. Unsupported purchasing stays disabled.
- [Commissions](https://docs.trychannel3.com/commissions): tracked click/purchase and retailer return window determine commission; advertised maximum rate is not recognized revenue or a guarantee of unified-checkout attribution.
- [Terms](https://www.trychannel3.com/terms), effectiveSeptember1,2026: significant catalog/output storage or redistribution is prohibited; purchases are between customer and merchant; output must be independently verified for commercial decisions. No numeric definition of significant was supplied. This is a bounded display cache, not catalog replication.
